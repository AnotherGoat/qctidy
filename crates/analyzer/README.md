# QCTidy Analyzer (`qctidy-analyzer`)

This crate abstracts and performs all metric analysis of the quantum circuits generated by `qctidy`. Its main goal is to extract vital statistics from the `Graph` that can then be consumed by:

- **Graphical interfaces (Web/TUI):** To generate "Before vs. After" reports of the simplifications.
- **Cost engines (Estimator):** To calculate execution prices on quantum hardware (AWS Braket, IBM Quantum) based on the gates used and the depth.

## Architecture and Components

This analyzer is designed as an independent package to keep separation of concerns and avoid overloading the core library. It has two main sub-modules:

### 1. `metrics.rs` (Data Structures)

Defines the strongly typed structures that represent the reports. All of them implement the standard derive traits (`Debug`, `Clone`, `Copy`, `PartialEq`).

- **`Metrics`**: Contains the basic counts of a circuit (number of qubits, depth, and specific gate instances such as X, Y, Z, Hadamard, etc.).
- **`DeltaMetrics`**: An optional structure (`Option<isize>`) that computes the difference (mathematical subtraction) between two metrics. Ideal for evaluating the "improvement" of a circuit after it has been run through the optimizer.
- **`DetailedMetrics`**: Offers a deeper analysis, computing:
  - Maximum density and density per column.
  - Percentages of rotational and controlled gate usage.
  - Concentration of complex gates (Toffoli / Ancilla).

#### Human-readable Format (`Display`)

The `std::fmt::Display` trait is implemented for `DetailedMetrics`, which lets any console interface (TUI) or CLI print an aesthetic and professional report of the circuit without writing additional formatting.

#### JSON Serialization

> **Serialization note:** All metric structures implement `serde::{Serialize, Deserialize}`. This guarantees that the analyzer is 100% ready to be integrated into the web server (`crates/server`), serializing metrics to JSON instantly for the frontend.

### 2. `calculator.rs` (Math Engine)

Contains the public functions (`calculate_metrics`, `calculate_detailed_metrics`, `compare_metrics`) that interact directly with the graph.

- **Efficiency and accuracy:** The calculation avoids creating heavy temporary arrays in memory. Instead, it iterates directly over `graph.iter_nodes()`. It groups gates intelligently to avoid "double counting" (for example, a CNOT gate that occupies 2 qubits is counted as a single logical gate by dividing by its weight).
- **Safety (zero-division protection):** All percentage and density calculations are protected by logic blocks. If a completely empty circuit is analyzed, the analyzer detects the possible division by zero and returns averages of `0.0`, ensuring the program never crashes (preventing runtime *panics*).

## Unit Tests (Testing)

The calculation engine has a battery of unit tests integrated in `calculator.rs` to guarantee mathematical accuracy under any condition:

- **`test_calculate_metrics`:** Programmatically builds a quantum circuit using the `GraphBuilder`, injecting Hadamard and CNOT gates. It then verifies strict assertions on the resulting counts (ensuring `metrics.hadamard_count == 1`, `metrics.cx_count == 1`, etc.).
- **`test_empty_graph_does_not_panic`:** A stress test (edge case) where an instantiated but gate-less graph is injected. It verifies that the zero-division protections activate correctly and the analyzer returns safe values without crashing.

## External dependencies

- `serde` (with the `derive` feature): Enables interoperability with web services.
